# geq-lab.github.io

This repository holds the website of the Geodynamics & Earthquake Lab, Earth Sciences, IIT Gandhinagar, served at https://geq-lab.github.io/ . The site is a plain set of pages: who we are, what we work on, the people, the papers, news, courses, funded projects, how to join and how to reach us. All of it is written in a handful of text files under `content/`, so a student can add themselves, a news item or a paper from the GitHub web editor without installing anything. HOWTO.md explains those three edits step by step.

The pages are generated by `build.py`, a short Python script with no framework behind it. It reads the YAML files and the BibTeX file in `content/`, renders the Jinja2 templates in `templates/`, crops and resizes the member photos and figures with Pillow (figures over 1600 px on the long side are scaled down, a PNG still over 300 KB is written with a 256-colour palette, and figures below the fold are lazy-loaded; a figure-heavy page such as Research still serves a few megabytes of images to a viewer who scrolls through all of it), and writes the result to `_site/`. A GitHub Actions workflow (`.github/workflows/pages.yml`) runs the script on every push to `main` and publishes `_site/` to GitHub Pages, so the site is live about a minute after a commit. To build locally: `pip3 install -r requirements.txt`, `python3 build.py`, then `python3 -m http.server -d _site` and open http://localhost:8000/ (`pip` and `python` on Windows). The server step matters: the pages link to `/static/...` from the site root, so opening `_site/index.html` straight from disk shows unstyled text. The build stops with a message naming the file when a YAML or BibTeX file is malformed, a required field is missing, a figure has no credit, a person's slug does not exist in `people.yml`, or a site-relative link points at a page or anchor that does not exist.

Layout: `content/` has `site.yml` (site-wide text, contact details and the home-page figure grid, each figure with a caption and a credit), `people.yml`, `research.yml` (the themes, each with a lead figure and a row of thumbnails, again each credited), `projects.yml`, `teaching.yml`, `awards.yml`, `join.md`, `publications.bib`, one Markdown file per news item in `news/` (optionally with a credited figure), and raw member photos in `photos/`. `static/` has the stylesheet, the logo and the group's own figures in `img/`. `templates/` has `base.html` and one template per page. SCHEMA.md is the contract for all of these: the fields each file takes, how the build treats them, and the house rules for content (plain prose, agencies but no industry client names, institutional emails only, every figure credited). `_site/` is generated and is not committed. Notes to the PI named `REVIEW_*.md` are git-ignored as well, so they never reach the public repository; keep any future notes of that kind under the same name pattern.

One-time setup on GitHub: the repository must be named `geq-lab.github.io` under the `geq-lab` organisation, and under Settings > Pages the source must be set to "GitHub Actions" (not "Deploy from a branch") before the first push to `main`; the workflow then publishes every push.
